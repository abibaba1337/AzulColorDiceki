# AzulDices

## Структура

```
azuldices/
├── index.html          — разметка страницы (без inline CSS/JS)
├── package.json         — нужен, чтобы Vercel понял api/roll.js как ES-модуль
├── css/
│   ├── styles.css        — все стили сайта (темы, панели, кубики и т.д.)
│   └── protection.css     — стили оверлея блокировки DevTools
├── js/
│   ├── state.js           — общие переменные (streak, isRolling, rollHistory).
│   │                        ПОДКЛЮЧАЕТСЯ ПЕРВЫМ — остальные скрипты от него зависят.
│   ├── ui.js               — настройки, темы, шрифты, курсор, панели, история в UI
│   ├── sounds.js           — звуковой движок (playSound)
│   ├── dice.js             — логика кубиков: теперь только запрашивает
│   │                        результат у сервера через fetch('/api/roll')
│   └── protection.js        — блокировка F12/правого клика/консоли (косметика)
└── api/
    └── roll.js              — SERVERLESS-функция Vercel. Вся генерация цвета
                               (Math.random(), веса, REPEAT_PENALTY) теперь
                               выполняется здесь, на сервере, а не в браузере.
```

## Почему это честно

Раньше `Math.random()` вызывался прямо в браузере — значит, любой человек
в консоли мог переопределить `Math.random`, подставить свой генератор
или вызвать функцию броска в цикле, пока не выпадет нужный цвет.

Теперь браузер ничего не считает сам. `js/dice.js` при броске делает:

```js
fetch('/api/roll', { method: 'POST', body: JSON.stringify({ count: 4 }) })
```

Сервер (`api/roll.js`) сам выбирает цвета через `Math.random()`, которая
выполняется в облаке Vercel — пользователь физически не может её увидеть
или изменить. Клиент получает уже готовый, "запечатанный" результат.

Количество кубиков сервер тоже не берёт от клиента бесконтрольно — оно
жёстко ограничено `MAX_DICE = 4`, так что подсунуть `count: 100` и
что-то сломать нельзя.

## Что осталось "как есть" (не требует защиты)

`js/ui.js`, `js/sounds.js`, `css/*`, кастомный курсор, темы, панели —
всё это чисто визуальные вещи. Подделать их через DevTools можно
(например, поменять цвет фона), но на честность результата броска это
никак не влияет, поэтому они не переносились на сервер.

`js/protection.js` (блокировка F12, контекстного меню, детект открытых
DevTools) — это дополнительный, чисто косметический барьер. Полностью
обойти блокировку клавиш в браузере невозможно (пользователь всегда может
отключить JS или использовать другой браузер/расширение), но это не
страшно: даже с открытыми DevTools подделать сам бросок больше нельзя,
потому что цвет уже выбран на сервере.

## Деплой на Vercel

1. Залейте папку `azuldices/` как репозиторий (например, в GitHub).
2. Зайдите на vercel.com → New Project → выберите репозиторий.
3. Vercel сам увидит `api/roll.js` и развернёт его как serverless-функцию,
   а `index.html` + `css/` + `js/` отдаст как статику. Никаких доп.
   настроек не требуется — Build Command можно оставить пустым.
4. После деплоя проверьте в DevTools → Network, что при клике "Бросить"
   уходит POST-запрос на `/api/roll` и в ответе уже готовый JSON с
   цветами — сам расчёт в `Sources` вы не найдёте, он теперь только
   на сервере.

## Локальная проверка

Можно поднять локально через Vercel CLI:

```
npm i -g vercel
vercel dev
```

Откроется `http://localhost:3000`, `/api/roll` будет работать так же,
как в проде.
